# Ours ablation — run guide (second server)

Everything needed to pull, launch the four arms assigned to this host, verify
that each switch actually took effect, and hand the results back.

---

## 1. What the ablation is

Ours has four independent axes. Axis 4 is applied post-hoc to a finished run,
so 3 axes x 2 = **8 base runs** cover the whole grid.

| axis | ON | OFF |
|---|---|---|
| 1. phase mode | **2phase**: train the new expert + its new router row, checkpoint, then retune the whole router on replay | **1phase**: new-task LM and router replay share every optimizer update (published Ours) |
| 2. KD init | expansion KD-init pass before each task | no KD step at all; the new expert starts from its random init |
| 3. replay source | **selfgen**: 500 records per task generated by the model right after it learned that task (BoS + anchor) | **real**: 500 records per task sampled from the original training data |
| 4. residual expert | post-hoc: add one no-op router row, tune the router on replay + backbone-BoS data | skip |

Two cells already exist and are **not** re-run:

| cell | run |
|---|---|
| 1phase / kd / gen | `selfgen_cl_frozen_20260901` (the lineage the final model comes from) |
| 1phase / kd / gen + residual | `residual_router_20260915/gen_res` |

The remaining seven base runs are split across two hosts. **This host runs the
four KD-off arms.**

| # | phase | kd | replay | script | ~wall (8 GPU) |
|---|---|---|---|---|---|
| 1 | 1phase | off | real | `run_arm_real.sh` | ~3.4h |
| 2 | 2phase | off | real | `run_arm_real.sh` | ~3.4h |
| 3 | 1phase | off | gen | `run_arm_gen.sh` | ~4.9h (train + generation) |
| 4 | 2phase | off | gen | `run_arm_gen.sh` | ~4.9h |

Run them **serially** — each arm uses all 8 GPUs.

---

## 2. Fixed conditions (do not change)

Every cell must match the final model's training condition, otherwise the
deltas measure the wrong thing (see `HP_ABLATION.md` trap #1: world size
changes the new expert/router random-init draw even at a fixed global batch).

* **world 8, global batch 64** — `--nproc_per_node=8`, micro 8, accum 1
* epochs `5,3,7,5,3,5,5,7`, rank 64 / alpha 128, top-k 1, seed 2025
* 500-record persistent memory, 5000-sample active stream, lr 2e-4

Both launchers hard-code these; only `PHASE`, `KD`, `NAME`, `GPU_LIST` are meant
to vary.

## 4. Run the four arms

Checkpoints land in `$ROOT/$NAME` (`ROOT` defaults to
`/data2/seonghyeonnoh/paper/ablation`; override if this host stores elsewhere).

```bash
cd trace/scripts/ablation

# 1) real replay, KD off
PHASE=1phase KD=off NAME=1phase_nokd_rep bash run_arm_real.sh
PHASE=2phase KD=off NAME=2phase_nokd_rep bash run_arm_real.sh

# 2) self-generated replay, KD off  (trains round t -> generates round t+1 -> ...)
PHASE=1phase KD=off NAME=1phase_nokd_gen bash run_arm_gen.sh
PHASE=2phase KD=off NAME=2phase_nokd_gen bash run_arm_gen.sh
```

Both scripts are **resumable**: rerunning skips finished rounds
(`<out>/<round>/lora_moe_meta.json` present) and picks up from the last one.
Progress is appended to `$ROOT/progress.log`; per-round logs are under
`$RUN/logs/` for gen arms and `$RUN/train.log` for real arms.

Run layout:

```
$ROOT/<NAME>/            (real arms)        $ROOT/<NAME>/model/   (gen arms)
  0 … 7/                     round checkpoints (post-phase2 for 2-phase arms)
  0_prephase2 … 7_prephase2/ 2-phase only: pre-router-retune checkpoints
  training_workload.json     per-round role/exposure accounting
  fixed_replay_memory/       real arms only: the 500 indices per task
$ROOT/<NAME>/gen/round_<t>/<task>/records.jsonl   gen arms: replay actually used
```

## 5. Verify every arm (required)

Both launchers call this automatically at the end, but run it again if a run
was resumed or interrupted:

```bash
cd trace
python scripts/ablation/verify_ablation_run.py $ROOT/2phase_nokd_rep \
  --expect-phase 2phase --expect-kd off --expect-replay real --log $ROOT/2phase_nokd_rep/train.log

python scripts/ablation/verify_ablation_run.py $ROOT/2phase_nokd_gen/model \
  --expect-phase 2phase --expect-kd off --expect-replay selfgen \
  --log "$ROOT/2phase_nokd_gen/logs/train_r*.log"
```

It must print `ALL CHECKS PASSED`. What each line proves:

| check | why it is proof, not a restatement of the flag |
|---|---|
| `phase1 froze old router rows` | compares `<t>_prephase2` router prefix against round `<t-1>`; must be **max drift 0.000e+00** |
| `phase2 moved router` / `left experts frozen` | `<t>` vs `<t>_prephase2`: router delta > 0, expert delta **0.000e+00** |
| `workload kd_init` | the `kd_init` role exists in `training_workload.json` only when KD ran (KD-off arms must show `[]`) |
| `workload phase-2 replay` / `no joint replay` | 2-phase writes the `router_replay_phase2` role and never the interleaved `router_replay` |
| `selfgen replay records used` | one `[selfgen] replay/KD for <task>: 500 generated records` line per past task per round |
| `real replay memory files` | `fixed_replay_memory/*.json` with exactly 500 indices per task |

Smoke results on the first host (2 rounds per arm) — all five arms passed,
including `phase1 drift 0.000e+00` and `phase2 expert delta 0.000e+00`.

## 6. Evaluation (after training)

TRACE sparse-15, 15 cells. **2-phase arms score the diagonal from the
pre-retune checkpoint** so plasticity is measured before the router
correction — the same convention the paper already uses for MoE-LPR:

```bash
cd trace
python scripts/run_ours_sparse15_optimized.py --run-dir $ROOT/<NAME> \
  --method <NAME> --gpus 0,1,2,3,4,5,6,7 \
  --diagonal-checkpoint-suffix _prephase2        # 2-phase arms ONLY
```

1-phase arms: omit the flag. LA = mean of the 8 diagonal cells, AA = mean of
the 8 final-row cells, F = mean over tasks 1-7 of (diagonal - final).

## 7. Residual-expert arm (axis 4, post-hoc)

Only after a base run finishes; follow `trace/scripts/residual/RECIPE.md`.
Short form (one GPU, ~25 min):

```bash
python scripts/residual/train_router_residual.py \
  --source $ROOT/<NAME>/7 \
  --replay "real:$ROOT/<NAME>/fixed_replay_memory" \
  --backbone scripts/residual/assets/backbone_bos_500.jsonl \
  --out $ROOT/<NAME>_res --n_residual 1 --replay_per_task 500 --backbone_n 500 \
  --batch 8 --accum 2 --lr 2e-4 --epochs 1
python scripts/ablation/verify_ablation_run.py $ROOT/<NAME>_res --residual
```

For gen arms the replay spec is
`gen:C-STANCE=<run>/gen/round_7/C-STANCE/records.jsonl,...,20Minuten=<new>` and
20Minuten must be generated first (RECIPE step 1). Do **not** pass
`--residual_only` — that is a different ablation.

## 8. Traps worth knowing

1. **`--ablation_kd_init off` forces `--v2_kd_loss_coeff 0`.** The V2-new
   sampler-pass validator asserts KD consumed its passes whenever the
   coefficient is positive; the launcher prints
   `[ablation] kd_init=off -> forcing --v2_kd_loss_coeff 1.0 -> 0`.
2. **The 1-phase joint path needs at least one replay exposure per optimizer
   update.** Shrinking the memory for a quick test trips
   `every-update replay needs at least one global exposure per optimizer update`.
   Keep memory 500 / global batch 64.
3. **selfgen arms refuse to start without `SELFGEN_ROOT`**, and real arms
   refuse to start *with* it — this guards the silent failure where a selfgen
   arm trains on real data. `run_arm_gen.sh` sets it per round.
4. **Ablation switches are part of the resume contract.** A gen chain resumes
   every round, so changing a switch mid-run aborts instead of silently
   producing a mixed run.
5. Generation reads anchor assets from `selfgen_v3_20260829` if present and
   otherwise falls back to `trace/scripts/selfgen/assets` (committed), so no
   file transfer is needed.

## 9. Handing results back

Per arm, the first host needs:

* `$ROOT/<NAME>/{0..7}/` and, for 2-phase arms, `{0..7}_prephase2/`
  (`pytorch_model.bin` + `lora_moe_meta.json` per directory)
* `training_workload.json`, `train.log` (or `logs/train_r*.log`),
  `fixed_replay_memory/` (real) or `gen/round_*/` (selfgen)
* the verifier output showing `ALL CHECKS PASSED`
* `sparse15_summary.json` once evaluated

Keeping `data_cache/` is unnecessary. Report LA / AA / F per arm and note
anything the verifier flagged as `WARN`.
